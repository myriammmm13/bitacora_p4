Cliente vs Servidor

En el modelo web, la comunicación ocurre entre dos roles principales:

Cliente

Es el navegador o aplicación que hace la solicitud. Envía peticiones HTTP al servidor y recibe la respuesta para mostrarla al usuario. Ejemplos: Chrome, Firefox, una app móvil.
Servidor

Es la máquina o programa que recibe las peticiones, las procesa y devuelve una respuesta. Ejemplos: Apache, Nginx, un servidor Spring Boot.

HTTP Request y HTTP Response

En la comunicación web, el cliente (generalmente un navegador) y el servidor interactúan mediante un modelo de petición y respuesta. El cliente envía una solicitud HTTP (request) al servidor, y este procesa la información y devuelve una respuesta (response). Este proceso ocurre cada vez que se carga una página web, se envía un formulario o se solicita cualquier recurso en Internet. La comunicación se basa en protocolos como HTTP o HTTPS.

HTTP Request (Petición) 
Una petición HTTP es el mensaje que envía el cliente al 
servidor para solicitar un recurso. 
Incluye información como el método (GET, POST), la ruta del 
recurso y encabezados con detalles adicionales.
HTTP Response (Respuesta) 
La respuesta HTTP es el mensaje que devuelve el servidor al 
cliente. 
Contiene un código de estado que indica el resultado de la 
solicitud, encabezados y, generalmente, el contenido 
solicitado como HTML, JSON u otros formatos.

Spring Boot

Spring Boot es un framework de Java que facilita el desarrollo de aplicaciones web y sistemas back-end. Permite crear aplicaciones de manera rápida, simplificando la configuración y reduciendo la cantidad de código necesario.

Incluye un servidor embebido, gestión automática de dependencias y herramientas para construir APIs y aplicaciones web de forma eficiente.

Spring MVC

Controladores: @Controller y @RestController

Los controladores son clases que manejan las peticiones HTTP entrantes. Spring Boot ofrece dos anotaciones principales según el tipo de respuesta que se quiera devolver al cliente.

@Controller Devuelve vistas (HTML)

Se usa cuando la respuesta es una página HTML renderizada, generalmente con Thymeleaf. El método retorna el nombre de la plantilla.

@Controller
public class PaginaController {
 
    @GetMapping("/inicio")
    public String inicio(Model model) {
        model.addAttribute("titulo", "Hola!");
        return "inicio"; // → inicio.html
    }
}
@RestController Devuelve datos (JSON / texto)

Combina @Controller + @ResponseBody. Cada método serializa el objeto retornado directamente como JSON, ideal para APIs.

@RestController
public class ApiController {
 
    @GetMapping("/api/saludo")
    public String saludo() {
        return "Hola desde la API";
    }
 
    @GetMapping("/api/datos")
    public Map<String, Object> datos() {
        return Map.of("id", 1, "nombre", "Ana");
    }
}
Diferencia clave: usa @Controller cuando tu app sirve páginas web con Thymeleaf, y @RestController cuando construyes una API que consume un frontend separado o móvil.
Motor de plantillas

Thymeleaf

Thymeleaf es un motor de plantillas Java que permite generar HTML dinámico del lado del servidor. Utiliza atributos especiales (th:*) directamente en el HTML, lo que hace que las plantillas sean válidas incluso sin servidor.

th:text — mostrar variables

Reemplaza el contenido del elemento con el valor del modelo.

<!-- Controlador -->
model.addAttribute("nombre", "María");
 
<!-- Plantilla -->
<p th:text="${nombre}">
    Nombre aquí
</p>
<!-- Resultado: <p>María</p> -->
th:each — listas / bucles

Itera sobre una colección y repite el elemento por cada ítem.

<!-- Controlador -->
model.addAttribute("frutas",
    List.of("Mango","Pera","Uva"));
 
<!-- Plantilla -->
<ul>
  <li th:each="f : ${frutas}"
      th:text="${f}"></li>
</ul>
th:if / th:unless — condicionales

Muestra u oculta elementos según una condición del modelo.

<!-- Controlador -->
model.addAttribute("activo", true);
 
<!-- Plantilla -->
<p th:if="${activo}">
    Usuario activo
</p>
<p th:unless="${activo}">
    Usuario inactivo
</p>
th:href — enlaces dinámicos

Genera URLs dinámicas con la sintaxis @{...} de Thymeleaf.

<!-- Enlace simple -->
<a th:href="@{/inicio}">
    Inicio
</a>
 
<!-- Enlace con parámetro -->
<a th:href="@{/usuario/{id}
    (id=${usuario.id})}">
    Ver perfil
</a>
th:value — campos de formulario

Vincula el valor de un campo de formulario a un atributo del modelo.

<form th:action="@{/guardar}"
      method="post">
  <input type="text"
         name="nombre"
         th:value="${usuario.nombre}">
  <button type="submit">
      Guardar
  </button>
</form>
th:fragment — reutilizar fragmentos

Define secciones reutilizables (como navbar o footer) e inclúyelas en otras páginas. 

<!-- fragments.html -->
<nav th:fragment="navbar">
    <a href="/">Inicio</a>
</nav>
 
<!-- otra página -->
<div th:insert="~{fragments
    :: navbar}">
</div>
Almacenamiento del cliente

Cookies

Las cookies son pequeños archivos de texto que el servidor envía al navegador del cliente para almacenar información entre solicitudes. Son útiles para recordar preferencias, sesiones de usuario o rastrear actividad.

Crear una cookie

Se crea un objeto Cookie, se configura y se añade a la respuesta HTTP. 

@GetMapping("/crear-cookie")
public String crearCookie(
        HttpServletResponse response) {
 
    Cookie cookie = new Cookie(
        "usuario", "Maria");
 
    cookie.setMaxAge(60 * 60 * 24); // 1 día
    cookie.setPath("/");
 
    response.addCookie(cookie);
    return "Cookie creada";
}
Leer una cookie

Se usa @CookieValue para obtener el valor directamente como parámetro. 

@GetMapping("/leer-cookie")
public String leerCookie(
    @CookieValue(
        value = "usuario",
        defaultValue = "Invitado")
    String usuario) {
 
    return "Hola, " + usuario;
}
Eliminar una cookie

Para eliminar una cookie se crea una nueva con el mismo nombre y MaxAge en 0. 

@GetMapping("/eliminar-cookie")
public String eliminarCookie(HttpServletResponse response) {
    Cookie cookie = new Cookie("usuario", null);
    cookie.setMaxAge(0);   // expira inmediatamente
    cookie.setPath("/");
    response.addCookie(cookie);
    return "Cookie eliminada";
}
Importante: las cookies se almacenan en el cliente y pueden ser leídas por el usuario. Nunca guardes información sensible como contraseñas directamente en una cookie. Usa setHttpOnly(true) para evitar acceso desde JavaScript.
Estado del servidor

Sesiones

Las sesiones permiten almacenar datos del usuario en el servidor entre diferentes solicitudes. A diferencia de las cookies, la información no viaja al cliente; solo se envía un identificador de sesión (JSESSIONID) que referencia los datos en el servidor.

Guardar en sesión 
@GetMapping("/guardar-sesion")
public String guardarSesion(
        HttpSession session) {
 
    session.setAttribute(
        "usuario", "Carlos");
    session.setAttribute(
        "rol", "ADMIN");
 
    return "Sesión iniciada";
}
Leer de sesión 
@GetMapping("/leer-sesion")
public String leerSesion(
        HttpSession session,
        Model model) {
 
    String usuario = (String)
        session.getAttribute("usuario");
 
    model.addAttribute("usuario", usuario);
    return "perfil"; // → perfil.html
}
Cerrar sesión / invalidar

Se llama a invalidate() para destruir la sesión y eliminar todos sus atributos. 

@GetMapping("/cerrar-sesion")
public String cerrarSesion(HttpSession session) {
    session.invalidate(); // elimina todos los atributos
    return "redirect:/inicio";
}
Tiempo de expiración

Se puede configurar cuánto tiempo dura inactiva una sesión antes de expirar.

// Configurar en application.properties:
server.servlet.session.timeout=30m
 
// O en código:
session.setMaxInactiveInterval(1800);

Inyección de dependencias (@Autowired)

La inyección de dependencias (DI) es un principio de diseño donde Spring se encarga de crear y proporcionar los objetos que una clase necesita, en lugar de que la clase los cree ella misma. @Autowired le indica a Spring que inyecte automáticamente la dependencia.

1. Crear el servicio

Se anota con @Service para que Spring lo registre como componente manejado.

@Service
public class SaludoService {
 
    public String obtenerSaludo(
            String nombre) {
        return "Hola, " + nombre + "!";
    }
}
2. Inyectar en el controlador

Spring detecta @Autowired e inyecta la instancia del servicio automáticamente. 

@Controller
public class HolaController {
 
    @Autowired
    private SaludoService saludoService;
 
    @GetMapping("/hola")
    public String hola(Model model) {
        String msg = saludoService
            .obtenerSaludo("Luis");
        model.addAttribute("mensaje", msg);
        return "hola"; // → hola.html
    }
}
Forma recomendada: inyección por constructor

Spring recomienda usar el constructor en vez de @Autowired en el campo, ya que facilita las pruebas unitarias y hace las dependencias explícitas. Con @RequiredArgsConstructor de Lombok esto es aún más limpio.

@Controller
public class HolaController {
 
    private final SaludoService saludoService;
 
    // Spring inyecta automáticamente cuando hay un solo constructor
    public HolaController(SaludoService saludoService) {
        this.saludoService = saludoService;
    }
 
    @GetMapping("/hola")
    public String hola(Model model) {
        model.addAttribute("mensaje",
            saludoService.obtenerSaludo("Luis"));
        return "hola";
    }
}
@Component Componente genérico manejado por Spring. Base de las demás anotaciones.
@Service Para clases de lógica de negocio. Semánticamente indica que es un servicio.
@Repository Para clases de acceso a datos. Añade traducción automática de excepciones.
¿Por qué usar DI? Al dejar que Spring gestione los objetos, el código queda desacoplado: puedes cambiar la implementación de un servicio sin tocar el controlador. Esto hace el código más fácil de mantener, probar y escalar.
