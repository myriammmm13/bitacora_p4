Cliente vs Servidor

En el modelo web, la comunicación ocurre entre dos roles principales:

Cliente

Es el navegador o aplicación que hace la solicitud. Envía peticiones HTTP al servidor y recibe la respuesta para mostrarla al usuario. Ejemplos: Chrome, Firefox, una app móvil.
Servidor

Es la máquina o programa que recibe las peticiones, las procesa y devuelve una respuesta. Ejemplos: Apache, Nginx, un servidor Spring Boot.

HTTP Request y HTTP Response

En la comunicación web, el cliente (generalmente un navegador) y el servidor interactúan mediante un modelo de petición y respuesta. El cliente envía una solicitud HTTP (request) al servidor, y este procesa la información y devuelve una respuesta (response). Este proceso ocurre cada vez que se carga una página web, se envía un formulario o se solicita cualquier recurso en Internet. La comunicación se basa en protocolos como HTTP o HTTPS.

HTTP Request (Petición) 
Una petición HTTP es el mensaje que envía el cliente al 
servidor para solicitar un recurso. 
Incluye información como el método (GET, POST), la ruta del 
recurso y encabezados con detalles adicionales.
HTTP Response (Respuesta) 
La respuesta HTTP es el mensaje que devuelve el servidor al 
cliente. 
Contiene un código de estado que indica el resultado de la 
solicitud, encabezados y, generalmente, el contenido 
solicitado como HTML, JSON u otros formatos.

Spring Boot

Spring Boot es un framework de Java que facilita el desarrollo de aplicaciones web y sistemas back-end. Permite crear aplicaciones de manera rápida, simplificando la configuración y reduciendo la cantidad de código necesario.

Incluye un servidor embebido, gestión automática de dependencias y herramientas para construir APIs y aplicaciones web de forma eficiente.

Spring MVC

Controladores: @Controller y @RestController

Los controladores son clases que manejan las peticiones HTTP entrantes. Spring Boot ofrece dos anotaciones principales según el tipo de respuesta.

@Controller Devuelve vistas (HTML)

Se usa cuando la respuesta es una página HTML renderizada, generalmente con Thymeleaf. El método retorna el nombre de la plantilla.

@Controller
public class PaginaController {
    @GetMapping("/inicio")
    public String inicio(Model model) {
        model.addAttribute("titulo", "Hola!");
        return "inicio";
    }
}
@RestController Devuelve datos (JSON / texto)

Combina @Controller + @ResponseBody. Cada método serializa el objeto retornado como JSON, ideal para APIs modernas.

@RestController
public class ApiController {
    @GetMapping("/api/saludo")
    public String saludo() {
        return "Hola desde la API";
    }

    @GetMapping("/api/datos")
    public Map<String, Object> datos() {
        return Map.of("id", 1, "nombre", "Ana");
    }
}
Diferencia clave: @Controller devuelve HTML, mientras que @RestController devuelve datos (JSON).
Motor de plantillas

Thymeleaf

Permite generar HTML dinámico del lado del servidor utilizando atributos especiales. Funciona perfectamente integrado con Spring Boot.

<!-- El valor de ${mensaje} reemplazará este texto -->
<div class="bienvenida">
    <p th:text="${mensaje}">
        Hola, este texto de ejemplo desaparecerá al cargar la página.
    </p>
</div>

Itera listas de objetos para crear elementos repetitivos.

<!-- Genera elementos de lista iterando la colección -->
<ul>
    <li th:each="f : ${frutas}" th:text="${f}">
        Manzana (Este es un texto de ejemplo de relleno)
    </li>
</ul>
IoC

Inyección de dependencias

Permite que Spring gestione automáticamente los objetos (Beans) y sus dependencias usando @Autowired.

@Service
                            
public class SaludoService {
    public String generarSaludo() {
        return "¡Hola, dependencia inyectada!";
    }
}

@Controller

public class MiControlador {
    
    @Autowired
    private SaludoService servicio;
}
Persistencia y Estado

Cookies y Sesiones

Mecanismos esenciales para mantener el estado en el protocolo HTTP, que por naturaleza es "stateless" (sin estado).

Archivos pequeños en el navegador.

Crear: Cookie c = new Cookie("user", "Maria"); response.addCookie(c);
Leer: @CookieValue("user") String user;

Almacenan datos temporalmente en el servidor.

Guardar: session.setAttribute("user", "Carlos");
Destruir: session.invalidate();
